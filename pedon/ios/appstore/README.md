# App Store release preparation

Status: preparing the first free iPhone release for **Felis AI LLC**. No App Store
submission or public availability is implied by this folder. The native source remains
under the repository's AGPL-3.0-only license; no distribution exception has been granted here.

## What is ready in source

- [Store copy](en-US.json), with the desktop companion requirement stated prominently.
- [Privacy policy](../privacy.md), also bundled for offline reading in Settings.
- [Support page](../support.md), reachable from Settings and the listing.
- App-local preferences reason `CA92.1` in `PrivacyInfo.xcprivacy`; no tracking or collected-data types.
- Original 1024-pixel opaque app icon. Its editable source is `../branding/make_icon.swift`.
- Camera and local-network purpose strings, iPhone device family, version/build, and system-only
  cryptography declaration in `../PedonAR/project.yml`.
- [Compiled archive check](../check_release.py), plus native bundle and UI tests.

This release is iPhone-only; iPad layouts have not been verified. iOS 18 remains the minimum
OS, while App Store uploads must use the iOS 26 SDK or later. These are separate requirements.

## Build a reviewable archive

From `pedon/`:

```bash
xcodegen generate --spec ios/PedonAR/project.yml
xcodebuild -project ios/PedonAR/PedonAR.xcodeproj -scheme PedonAR \
  -configuration Release -destination 'generic/platform=iOS' \
  -archivePath /tmp/PEDON.xcarchive CODE_SIGNING_ALLOWED=NO archive
python3 ios/check_release.py /tmp/PEDON.xcarchive
```

An unsigned archive is for inspection; it cannot be uploaded. In Xcode select the Felis AI
organization and automatic signing, archive, then use Organizer → Distribute App → App Store
Connect. Keep team IDs, account details, distribution certificates and profiles local.
Use the current project version for the initial upload and increment the build for each later
upload of that marketing version. Do not embed the Mac address or any user's site in the app.

## Remaining release gates

1. Confirm App Store distribution rights. AGPL source availability alone does not resolve
   App Store usage restrictions. The owner can authorize a separate license for the official
   binary if they control all relevant rights. Obtain that explicit decision before upload;
   do not silently relicense the source or contributors' work. The current native target uses
   Apple frameworks only and has no external Swift package dependencies. Review provenance
   again if any are added. See the [FSF's App Store discussion](https://www.fsf.org/blogs/licensing/more-about-the-app-store-gpl-enforcement)
   for the issue's background; it is historical, not a determination about this release.
2. In App Store Connect, create/confirm the app under the Felis AI organization, with the
   bundle ID generated by `project.yml`. Check name availability; the JSON is proposed metadata.
3. Complete distribution signing and Apple upload validation. A local development install is
   not evidence that an App Store certificate/profile is ready.
4. Provide review access and App Store screenshots without publishing a private site. The app
   depends on a desktop export and real environment. Supply a reproducible sample/setup and
   an actual-device video demonstrating scan matching, camera permissions, guide selection,
   scan overlay, and saved-position recovery. A simulator preview is not evidence of physical
   tracking. Do not claim a built-in demo exists until it has been implemented and tested.
5. Fill in App Review contact details privately in App Store Connect. No sign-in is required
   by the app itself. Explain the Mac dependency and reference video in Review Notes.
6. Confirm the organization's trader status/territories and answer Apple's current age-rating
   questionnaire. Proposed category is Productivity; the app has no ads, purchases, messaging,
   public content feed, or unrestricted in-app browser. Apple computes the rating.
7. Set Free pricing, enter privacy answers after reviewing the actual submitted binary, and
   verify the support/privacy URLs are public and reachable. For the audited native build,
   the proposed answer is **No, we do not collect data from this app**. App-local AR processing
   is not off-device collection; the desktop server is selected and operated by the user.
8. Review the complete listing/build, choose manual release, then submit to App Review.
   Do not confuse TestFlight upload, review approval and public release.

## Review notes draft

PEDON is a free companion to the open-source PEDON desktop landscape editor. There is no
in-app account, purchase, subscription, advertising or developer-operated backend. The app
downloads a design and original site scan from a local PEDON desktop server chosen by the user.
Camera access supports AR alignment; local-network access supports that download. The app
saves the design and AR alignment locally for offline reopening. App Settings includes an
offline privacy policy and support link.

Before submission, attach the actual-device walkthrough and complete the reviewer-access
instructions with the tested sample. Do not submit these unfinished directions as review notes.
